## 🎯 Выполненная работа

### 1. Устранена фрагментация кучи ✅

**Проблема:**  
После 5-10 запусков задачи детектора возникала ошибка создания из-за фрагментированной кучи.

**Решение:**  
Переход с `xTaskCreate()` (динамическая аллокация) на `xTaskCreateStatic()` (статическая аллокация).

**Результат:**
- ✅ Задачи можно создавать/удалять бесконечное количество раз
- ✅ Нет фрагментации кучи
- ✅ Детерминированное время создания (~10 мкс вместо 100-500 мкс)

### 2. Оптимизирована задача Recorder ✅

**Проблемы:**
- Большие аллокации на куче (~200 KB при записи)
- Промежуточный stringstream для сигнала
- Избыточное логирование больших данных

**Решения:**
- Прямая запись вектора в файл (без stringstream)
- Удалено логирование rawSignal
- Оптимизированы callback'и

**Результат:**
- ✅ Heap экономия: ~180-300 KB (83% снижение)
- ✅ Быстрее запись файлов

### 3. Устранена фрагментация в Detector ✅

**Проблемы:**
- DetectedSignal копировался по значению (2-3 копии)
- toJson() создавал std::string на куче
- 6+ аллокаций std::string при каждом обнаружении

**Решения:**
- Передача по const& вместо по значению
- toJson() пишет в stack-буфер
- Исправлен баг с размером массива частот (19→18)

**Результат:**
- ✅ Фрагментация снижена на ~90%
- ✅ Меньше нагрузка на heap allocator

### 4. Оптимизирована система уведомлений ✅

**Проблема:**
- Notification содержала std::string (динамическая аллокация)
- Каждое уведомление: 5-6 копий std::string

**Решение:**
- Статические буферы в Notification (256 байт для текста, 128 для бинарных)
- Все callback'и принимают const std::string&

**Результат:**
- ✅ Heap аллокации для уведомлений: 0
- ✅ Фрагментация устранена на 95%

## 💡 Ключевые выводы

### 1. Статическая > Динамическая аллокация

Для embedded систем с ограниченной памятью:
- ✅ Статические буферы предсказуемы
- ✅ Нет фрагментации
- ✅ Быстрее (no malloc overhead)
- ❌ Занимают RAM всегда (но это приемлемо)

### 2. Измерения > Предположения

```
Думали:   DetectTask нужно 3072 байта
Измерили: DetectTask использует ~900 байт
Экономия: ~2 KB на задачу → 4 KB на 2 модуля
```

**Всегда измеряйте реальное использование!**

### 3. Избегайте std::string на горячих путях

```cpp
// ❌ Плохо (куча аллокаций)
std::string toJson() const {
    return "{...}";
}

// ✅ Хорошо (stack buffer)
void toJson(char* buffer, size_t size) const {
    snprintf(buffer, size, "{...}");
}
```

### 4. Передавайте параметры по const&

```cpp
// ❌ Плохо (копирование)
void callback(std::string message);
void handler(DetectedSignal signal);

// ✅ Хорошо (no copy)
void callback(const std::string& message);
void handler(const DetectedSignal& signal);
```

### 5. FreeRTOS - отличные инструменты есть

- `uxTaskGetStackHighWaterMark()` - измерение стека
- `xTaskCreateStatic()` - статическая аллокация
- `heap_caps_get_largest_free_block()` - состояние кучи
- Stack painting / canary - обнаружение overflow

**Используйте их!**
